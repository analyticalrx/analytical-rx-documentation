Review Scope

This Airtable review is organized into one index and three detail documents: tables, interfaces, and automations.

The table and interface material comes from Airtable metadata. No underlying record values were fetched. Automation material comes from screenshots because the current Airtable MCP tooling exposed interface/page metadata but not full automation definitions.

The client is using Airtable temporarily and may stop the subscription. We are treating this material as an archived product reference for Phase 1 and later phases, not as a live system dependency, migration source, or database schema to copy directly.

Do not fetch Airtable records until the client confirms whether the base contains PHI, whether Airtable is covered by the right HIPAA configuration, and what data we are allowed to migrate or inspect.

Phase 1 Direction

  1. Use Pharmacies and People as the store and staff foundation.
  2. Build role-specific dashboards around Daily Sales, KPI Scorecard, Tasks, Financial Periods, Compliance Items, and Documents.
  3. Replicate the core workflow automations as backend scheduled jobs and record-triggered rules.
  4. Start with operational visibility and manual/imported dashboard data before advanced analytics.
  5. Use the remaining Airtable modules and workflow ideas as a future-phase backlog reference, even if the Airtable subscription is discontinued.
  6. Later enrich Daily Sales, Rx Metrics, AR, payer, and drug-level reporting from PrimeRx API, webhooks, and SFTP feeds.

Important Security Notes

  • Metadata review did not pull record values, so no patient, staff, vendor, or document record contents were copied into this repository.
  • People, Doctor Offices, Vendors, and attachment fields may contain personal or sensitive business contact data.
  • Compliance Logs include drug names and controlled-substance style fields. We need client confirmation before importing records.
  • Attachment fields can contain unknown document content. Files should move to restricted object storage with metadata in the database.
  • Notes/comments fields should be reviewed carefully because free text can contain PHI even when the schema itself does not require it.
