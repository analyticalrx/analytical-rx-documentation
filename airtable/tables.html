Airtable Tables

Schema-level review of Airtable tables, fields, linked relationships, and software implications.

Source And Scope

This document uses Airtable base metadata only: table names, field names, field types, select options, linked-record relationships, and view names. It does not include record values.

Airtable is a temporary reference prototype. These tables capture product intent and future module ideas; they are not a migration source and should not be copied one-to-one into the AnalyticalRx database.

Fields and relationships here describe the current Airtable setup. They should guide our product model, but we should not build a generic Airtable clone.

Data And Security Notes

  • People has emails, phones, roles, employment status, and staff links. Access should be role-restricted.
  • Doctor Offices has doctor, contact, outreach, and referral information. Treat it as sensitive business relationship data.
  • Documents, Compliance Items, SOPs, Tasks, and related attachment fields should move to secure object storage with metadata in the database.
  • Compliance Logs may include drug and controlled-substance operational information. Do not import records until the client confirms allowed scope.
  • Financial, AR, KPI, and sales tables should be visible only to owner/bookkeeper/admin roles unless the client explicitly allows broader access.
  • Free-text fields such as notes and comments can contain PHI or sensitive context even when the field name does not imply it.
