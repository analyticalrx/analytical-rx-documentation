pgAdmin ERD Generation Guide

Steps to generate the canonical event database ER diagram from the PostgreSQL schema using pgAdmin.

Purpose

pgAdmin creates ER diagrams from a live PostgreSQL database. To generate the diagram, first create the MVP schema in a development database, then use pgAdmin's ERD tool to generate and export the diagram.

Use a local or development database only. Do not run the draft schema in a production database without migration review.

Files Used

File Purpose
schemas/mvp_canonical_event_schema.sql SQL DDL used to create the tables and foreign key relationships in PostgreSQL.
database/canonical-event-table-dictionary.html Field definitions and access restrictions to review alongside the pgAdmin ERD.
pgadmin/analytical-rx-local-server.json pgAdmin server registration file for this local design database.
scripts/generate_postgres_erd.rb Optional CLI generator that reads the live PostgreSQL schema and creates a full-column ERD with Graphviz.

Prerequisites

  • PostgreSQL client/server tools installed.
  • Graphviz installed if generating the checked-in ERD files from the command line.
  • pgAdmin 4 installed.
  • Access to a PostgreSQL development database.
  • Permission to create schemas, tables, indexes, and the pgcrypto extension in that development database.

Step 1: Create A Development Database

Create or choose a non-production database, for example:

createdb analytical_rx_design

This database is only for visualizing and validating the table relationships.

Step 2: Run The Schema SQL

From the command line, the schema can be loaded with:

psql -d analytical_rx_design -v ON_ERROR_STOP=1 -f schemas/mvp_canonical_event_schema.sql

Or use pgAdmin:

  1. Open pgAdmin.
  2. Connect to the PostgreSQL server.
  3. Select the development database.
  4. Open Query Tool.
  5. Open or paste schemas/mvp_canonical_event_schema.sql.
  6. Execute the SQL.
  7. Refresh the database tree in pgAdmin.

After execution, pgAdmin should show the review tenant schema:

tenant_template

Step 3: Open The Database In pgAdmin

  1. Open pgAdmin 4.
  2. In the left browser tree, open Servers.
  3. Select AnalyticalRx Local Design.
  4. Open Databases, then select analytical_rx_design.

If the server is not visible, copy pgadmin/analytical-rx-local-server.json, replace CHANGE_ME_LOCAL_POSTGRES_USER with your local PostgreSQL username, then import it using pgAdmin's import server option or this desktop command:

/Applications/pgAdmin\ 4.app/Contents/Frameworks/Python.framework/Versions/3.13/bin/python3.13 \
  /Applications/pgAdmin\ 4.app/Contents/Resources/web/setup.py \
  load-servers pgadmin/analytical-rx-local-server.json \
  --sqlite-path ~/.pgadmin/pgadmin4.db

Step 4: Generate The ERD In pgAdmin

  1. Select the database in pgAdmin.
  2. Open the ERD tool from pgAdmin. Depending on pgAdmin version, use the Tools menu or right-click the database and choose the ERD option.
  3. Generate the ERD for the database so pgAdmin fetches all tables and foreign key links.
  4. Use Auto align to arrange the diagram.
  5. Use Show details to include columns in the visual model.
  6. Use Cardinality Notation and choose Crow's Foot notation if preferred.

pgAdmin can generate an ERD from an existing database, schema, or table. For this MVP model, schema-level generation against tenant_template is easiest because all tenant-owned tables live in one schema.

Step 5: Export The Diagram

  1. Use pgAdmin's ERD Save As option if you want a reusable pgAdmin ERD project file.
  2. Use Download image to export the diagram as an image for sharing.
  3. Name the exported image something like canonical-event-pgadmin-erd.png.

Generated ERD Files

A full-column ERD was also generated from the live PostgreSQL database using psql and Graphviz. These files are useful when someone wants to review the exact model without opening pgAdmin.

File Purpose
diagrams/canonical-event-postgres-erd.svg Zoomable full-column ERD with all tables, columns, key markers, and foreign key connections.
diagrams/canonical-event-postgres-erd.png PNG export for quick review or attaching to documents.
diagrams/canonical-event-postgres-erd.dot Graphviz source generated from PostgreSQL metadata.

Regenerate these files after schema changes with:

ruby scripts/generate_postgres_erd.rb

Expected Relationships

Relationship Meaning
tenant to pharmacy One tenant can have many pharmacies.
tenant to drug and payer Drug and payer lookup rows are tenant-scoped for source matching and isolation.
tenant to raw_payload_archive Raw payload metadata belongs to one tenant.
pharmacy to raw_payload_archive Raw payload metadata may be linked to one pharmacy when known.
pharmacy to source_rx_reference Restricted prescription/fill source references belong to one pharmacy.
source_rx_reference to ingestion_event An ingestion event can link to the restricted prescription/fill reference used for API enrichment.
raw_payload_archive to ingestion_event An ingestion event can link to raw payload archive metadata if raw retention is enabled.
ingestion_event to pharmacy_event One processed ingestion event should create at most one pharmacy event row.
drug to pharmacy_event A pharmacy event can link to a normalized drug when available.
pharmacy_event to event_payment A pharmacy event can have multiple payment rows for primary, secondary, tertiary, patient pay, cash, or other components.
payer to event_payment Insurance payment rows can link to a payer. Cash payment rows intentionally keep payer_id null.

If pgAdmin Does Not Show Relationships

  • Confirm the SQL ran successfully.
  • Confirm the foreign keys exist under each table's constraints.
  • Refresh the database tree before generating the ERD.
  • Generate ERD for the tenant schema, for example tenant_template, because the model keeps tenant-owned tables together in one schema.
