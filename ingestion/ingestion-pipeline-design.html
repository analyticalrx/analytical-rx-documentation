PrimeRx Ingestion Pipeline Design

This document defines the ingestion path for PrimeRx and Micro Merchant data into the AnalyticalRx platform.

Scope

The pipeline must support three ingestion modes:

  1. Webhooks for near-real-time event triggers.
  2. API sync for backfill, enrichment, and reconciliation.
  3. SFTP historical and daily batch feeds after field specification and setup approval.

Goals

  • Accept source data safely
  • Prevent PHI leakage into canonical dashboard storage
  • Normalize source payloads into a canonical model
  • Support initial load, daily sync, and missed-event recovery
  • Produce audit logs and exception reports
  • Keep the ingestion layer resilient to retries, duplicates, and schema drift

Ingestion Flows

1. Webhook Flow

Webhooks are the primary near-real-time trigger.

Behavior:

  • Receive HTTPS POST requests
  • Authenticate the sender
  • Persist the raw payload in restricted quarantine storage
  • Return 2xx quickly
  • Process the payload asynchronously
  • Deduplicate events
  • Suppress PHI before downstream use
  • Optionally call the API to enrich incomplete webhook payloads

2. API Flow

API sync covers backfill and reconciliation.

Behavior:

  • Authenticate using PrimeRx API credentials
  • Pull prescription, patient, payer, drug, prescriber, pharmacy, and status data
  • Support paging and incremental windows if available
  • Support manual backfill and scheduled syncs
  • Store raw responses in restricted quarantine
  • Apply the same PHI and validation controls as webhook events

3. SFTP / Batch Flow

PrimeRx supports historical and daily feed file options through SFTP. Once the required field specification, setup cost, and automation details are approved, this channel should be used for:

  • Historical load
  • Large backfills
  • KPI rebuilds
  • Source reconciliation

Pipeline Stages

Stage 1: Ingress

Ingress services are thin by design.

  • Webhook receiver
  • API sync worker
  • Bulk file receiver, if available

Responsibilities:

  • Authentication
  • Request validation
  • Durable write to quarantine
  • Fast acknowledgement

Stage 2: Quarantine

Raw payloads are isolated here.

Responsibilities:

  • Hold PHI-containing data briefly
  • Support replay
  • Preserve original payloads for audit
  • Restrict access to ingestion operators only

Stage 3: PHI Filter

This is the trust boundary.

Responsibilities:

  • Remove direct patient identifiers
  • Bucket or generalize sensitive fields
  • Convert source IDs into internal IDs or pseudonyms
  • Reject payloads that violate policy

Stage 4: Validation and Mapping

Responsibilities:

  • Validate payload shape
  • Map source fields to canonical columns
  • Detect duplicates and replays
  • Normalize enums and status values
  • Emit transformation exceptions

Stage 5: Canonical Load

Responsibilities:

  • Upsert into fact and dimension tables
  • Preserve import lineage
  • Track source timestamps and ingestion timestamps
  • Support replay-safe writes

Stage 6: Reconciliation

Responsibilities:

  • Compare webhook-driven events with API or bulk source truth
  • Detect missing, duplicated, or reversed events
  • Recompute KPIs when needed
  • Write reconciliation results to audit logs

Data Handling Rules

  • Do not allow patient name, street address, DOB, phone, email, driver license, prescription images, or free-text identifier fields into canonical dashboard storage
  • Use age bands instead of DOB
  • Use ZIP3 or region grouping instead of full address when needed
  • Use internal IDs or approved pseudonymous tokens for continuity
  • Mark all source fields as allowed, excluded, or transformed before implementation

Failure Modes

  • Invalid auth
  • Bad JSON or schema mismatch
  • Duplicate webhook delivery
  • Out-of-order event delivery
  • API rate limit or timeout
  • Missing bulk batch file
  • Reversal or cancellation after initial receipt
  • PHI leakage attempt
  • Source field drift after vendor update

Each of these should route to an exception queue or audit record, not silent failure.

Operational Questions For PrimeRx

  • Do you support a bulk historical export or batch send?
  • Do webhooks support retries, replay, and event IDs?
  • Can webhook payloads suppress PHI?
  • Can API responses suppress PHI?
  • Are incremental sync endpoints available?
  • What is the source of truth for reversals, rejections, and adjustments?
  • Can the API or bulk feed be used for daily reconciliation?
